# Neovim IDE Implementation Plan

> Executed natively (user said "do it"). Steps use checkbox syntax.

**Goal:** Turn the nvim config into a debloated TUI Zed with one tmux-style key grammar.

**Architecture:** Small focused lazy.nvim plugins; specs in `lua/plugins/`, every
global key in `lua/config/keymaps.lua`, helpers in `lua/config/{lsp,terminal,run}.lua`,
chrome colors from `~/.rice`.

**Tech Stack:** Neovim 0.12.5, lazy.nvim, Lua.

**Spec:** `docs/superpowers/specs/2026-10-03-nvim-ide-design.md`

## Global Constraints

- Never bind `<C-Space>` or override `<C-h/j/k/l>` (tmux vim-modes / navigator).
- No AI plugins. No format-on-save (removed deliberately in f153c81).
- Code syntax colors untouched; rice themes chrome only.
- New files in the stow package need `stow -R --no-folding -t ~ nvim` (per-file links).
- Plugin modules are only `require`d inside keymap functions (keeps lazy-loading).

## Review Focus

1. Startup in a non-git dir / on a file with no LSP or parser: no errors, keys still defined.
2. `nvim <dir>` opens the tree instead of netrw.
3. Closing the last real buffer with tree/outline/terminal open quits cleanly (no orphan panel windows).
4. `␣rt` on a line with no enclosing test: clear message, nothing sent.
5. Theme switch (`apply-theme <x>` then restart): bufferline/lualine/panels take the new colors.

Each is checked in Task 7's live run.
